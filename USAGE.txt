nvEmacs — Usage
===============

How to search.  Case and accents are ignored everywhere.  See COMMANDS.txt
for keys and SETTINGS.txt for settings.


Simple search
-------------

  whale             notes containing "whale", also inside longer words
  whale ishmael     notes containing both, anywhere, in any order
  "blue whale"      that exact phrase, even when a line break splits it

A space means AND: a note must contain every word.  Plain words search a
note's title and body.  They do not search its header, keys or comments.
To leave words out, or to find one word or another, see Boolean search.


Boolean search
--------------

Boolean search combines words with AND, NOT and OR.

AND is the space between words, as in simple search.  There is no AND
keyword: a typed AND is searched as the word "and".

  whale ishmael     notes with both "whale" and "ishmael"

NOT is a minus sign in front of a word, a quoted phrase, a search prefix or
a group.  It leaves those notes out.

  -whale            notes without "whale"
  -"blue whale"     notes without that phrase
  whale -ishmael    notes with "whale" but not "ishmael"
  -5                notes without "5"
  -tag:old          notes without a tag starting with "old"

A word follows the same rule as plain search: -whale looks at the title and
body, not the header, keys or comments.

The minus means NOT only at the start of a word, and only before a letter,
digit, quote or opening parenthesis.  To search for text that starts with a
hyphen, put it in quotes.  There is no backslash escape.

  "-whale"          the text -whale
  "-5"              the text -5
  "-"               a hyphen
  well-known        the text well-known: the hyphen is inside the word
  --verbose         the text --verbose: another hyphen follows the first
  ->                the text ->: a symbol follows the hyphen
  -                 ignored while you are still typing

OR is a capital OR between the words of a group in parentheses.

  (whale OR shark)          notes with "whale", "shark" or both
  (whale OR shark) ocean    either one, and also "ocean"
  ("blue whale" OR orca)    phrases too
  (tag:work OR dir:work)    and every search prefix
  -(whale OR shark)         notes with neither: the same as -whale -shark

A lowercase or, and an OR outside parentheses, is searched as the word
"or": this or that, this OR that, (this or that).

Groups must be explicit.  A group is either all OR or all spaces, never
both, so nothing depends on which one binds tighter:

  (whale OR shark ocean)    not allowed: which two go together?
  (whale OR (shark ocean))  whale, or shark with ocean
  ((whale OR shark) ocean)  whale or shark, with ocean

A minus before a group of words joined by spaces is not allowed either:

  -(whale shark)            not allowed: leave out both, or notes with both?
  -whale -shark             leave out every note with either word
  (-whale OR -shark)        leave out only the notes with both

Such a search does not run.  The list stays as it was, and the echo area
says why.

Two kinds of search run, with a warning in the echo area:

  (whale OR -shark)         a minus inside OR matches almost every note:
                            here, every note without "shark"
  (whale AND shark)         AND is searched as the word "and"

Parentheses group only at the edge of a word, so f(x) and :) are plain
text.  A group left open runs to the end, so the list narrows while you
type, and a trailing OR waits for its next word.  Quotes make parentheses
and OR plain text:

  "(1)"                     the text (1)
  "(this OR that)"          that text, parentheses included

With parentheses in the search, Return does not create a note when nothing
matches: C-c C-n does, titled with the search.  Return opens nothing while
the search has an empty group, such as -( with nothing after it yet.

Each of these messages ends with a pointer here.  M-x nvemacs-usage shows
this file in the note pane, at this section after one of them.


Search prefixes
---------------

  tag:     a tag, by the start of its name
  key:     a key's name, by its start
  meta:    the value of any key, or a comment in the header
  dir:     a folder, and every folder inside it
  created: the note's Created date
  added:   the date nvEmacs first saw the file
  modified: the date the file last changed

A minus before any prefix leaves those notes out, as -tag:old does.

Any other word with a colon, such as http:, is plain text.  To search for
text that looks like a prefix, put it in quotes:

  key:string        notes with a key whose name starts with "string"
  "key:string"      notes containing the text key:string


Keys and values
---------------

A key is a named field: #+Notes: in Org, or notes: in Markdown front matter.
Every key is captured, including ones you invent.  M-x nvemacs-keys-list
shows them all.

  key:notes         notes that have a key named Notes
  meta:whale        notes with "whale" in any key's value
  meta:"blue whale" notes with that phrase in any key's value
  key:"date created"  a key name with a space in it
  -key:draft        leave out notes that have a key named "draft"
  -meta:whale       leave out notes with "whale" in a key's value

Be careful when combining the two:

  key:notes meta:whale

This finds notes that have a Notes key AND have "whale" in some value.  The
whale may be in a different key, such as Author.  A search cannot be limited
to the value of one key.

Nested front matter is stored with dots, so author: followed by an indented
name: is the key author.name.  key:author finds it, and each item of a list
is its own value.

Org keys count anywhere in a note, except inside source, example and export
blocks.  meta: finds their values wherever they are.


Folders
-------

dir: lists the notes in a folder, including its subfolders.  Words narrow
the list.  The folders are your watched folders and every folder inside
them.  Case is ignored.

  dir:work          a folder whose name starts with "work"
  dir:work/         the folder named exactly "work"
  dir:work whale    notes with "whale" in those folders
  dir:2026/work     a folder starting with "work" right inside "2026"
  dir:notes/2026/   folders named "2026" right inside "notes"
  -dir:archive      every note except those in such folders

Without a trailing slash, the last part is the start of a name, and it
matches only a watched folder or a folder inside one.  With a trailing
slash, every part is a whole name, and the names may be anywhere in the
folder's path, even above the watched folder.

For example, with these watched folders:

  this/is/path/to/directory1
  path/to/directory2
  a/b/third

  dir:direc         directory1 and directory2
  dir:th            third, but not "this", which is above directory1
  dir:b/thi         third
  dir:path/to/      directory1 and directory2
  dir:is/           directory1

To mean exactly one place, start with / or ~, and the path is matched from
the start:

  dir:~/path/to/    only directory2, if that is where it is
  dir:"~/My Notes/" quotes for a name with a space


Dates
-----

created:, added: and modified: take the same forms.  Both ends of a range
are included, and a partial date means its whole span.

  created:2026                 all of 2026
  created:2026-11              November 2026
  created:2026-11-23           that day
  created:2026-10..2026-12     October through December
  created:2026-01-15..2026-02  January 15 through February 28
  created:>=2026-01            January 2026 or later
  created:<2026-01             before January 2026
  created:-30d                 the last 30 days (also w, m, y)
  created:2026-11~1m           one month either side: October through December
  created:2026-01-15~15        15 days either side: Dec 31 through Jan 30
  created:2027-01-01>1m        forward one month: Jan 1 through Feb 1, 2027
  created:2027-01-01<1m        back one month: Dec 1, 2026 through Jan 1, 2027
  -created:2026-11             leave out notes created in November 2026

A number with no unit takes the date's precision: days for a full date,
months for 2026-11 and years for 2026.  A date that cannot be read, such as
created:2026-13, finds nothing, and the status line says why.


Created and Date
----------------

A note's date comes from its header.  In Org, the header is the block of
lines before the first blank line.  In Markdown, it is the front matter.

Created is used first, then Date.  nvEmacs writes new notes with both:

  #+Created:  2026-11-23-10:30:45
  #+Date:     [2026-11-23 Mon 10:30]

In Markdown:

  created: 2026-11-23-10:30:45
  date: 2026-11-23T10:30:45-05:00

Created is nvEmacs's own key.  Date is in the form Org or Markdown tools
expect, and those tools may change it.  nvEmacs cannot do anything if an
outside tool changes either key.

A time zone offset is accepted but not required.  A date without one is
local time wherever you are, and it shows and matches as written.


Comments
--------

Comments are left out of plain search.  M-x nvemacs-index-comments turns
comment search on or off.  It asks before rebuilding the index, remembers
your choice and says which state it is now in.

  Org        a line starting with "# ", or #+begin_comment to #+end_comment
  Markdown   <!-- to -->, which may span lines
  Text       no comments: every line is searched

A comment in an Org header is always header: meta: finds it, and plain
search does not.  In Org, "* COMMENT" is an ordinary section.


Search history
--------------

nvEmacs records your searches so you can look back at them and run them
again.  History is on for now, while it is being tested.  M-x
nvemacs-searchbar-history turns it on or off, remembers the choice and says
which state it is in.  Turning it off asks first, then deletes the history
file.

  M-p          on the search line: the previous search
  M-n          on the search line: the next one, then what you had typed

  >>> M-p and M-n work only on the search line.  On a result row, and in
  >>> your notes, they keep their usual meaning.

M-x nvemacs-searchbar-history-list shows past searches in place of the
notelist, newest first, with a colored bar down the left so it is not
mistaken for your notes.  Type to filter them, with words, "quotes" and
-word as in search.  On a row, RET runs that search, d deletes it from the
history, and q returns.  C-c C-c also returns.  Each row shows the time,
how many times it was run (x3), how it ended, and how many rows it showed.
A + after that number means more matches were still being found.

What counts as one search:

  - Typing adds to the search in progress, however long you pause.
  - Deleting within a second of your last keystroke fixes a typo.
  - Deleting after a pause of a second or more starts a new search.
  - A search ends when you open a note, edit one, clear the search line or
    quit.  It is then written to the history.
  - Moving through rows, scrolling or resting on a note does not end it.
  - The title shown for a selected row is never recorded.

Running a search again moves it to the top and counts it, rather than adding
a copy.  Searches differing only in case or spaces count as the same one.
The history keeps the newest 100 distinct searches
(nvemacs-searchbar-history-size).

The file is history.jsonl in nvemacs-data-directory, readable only by you,
one search per line in JSON after a first line that describes it.  Two
limits are worth knowing:

  - Deleting the file does not guarantee the text is gone.  On a Mac,
    overwriting usually writes new blocks, and snapshots, Time Machine or a
    synced folder may keep copies.
  - Two Emacs sessions running nvEmacs share one file, and a search can
    occasionally be lost.


Malformed notes
---------------

nvEmacs lists notes whose header needs attention in malformed.org, in
nvemacs-data-directory.  The home page links to it, and
M-x nvemacs-index-malformed writes and opens it.  Each section says what is
wrong and how to fix it.  nvEmacs never edits those notes.

  - Title, Created, Date or file tags outside the header
  - More than one Title, Created or Date in the header
  - A Created or Date with no readable date in the note
  - A header with no Created or Date (listed as missing a date)

Other keys can hold anything.  A misspelled #+Crated: is simply a key named
Crated, so that note is listed as missing a date.
